## SQL scope and transaction

The patch owns one `BEGIN`/`COMMIT`, with 5-second lock and 15-second statement
limits. Run it as the existing trusted function owner. It takes an exclusive lock
on the attempts table and fails on unknown original function bodies or an already
installed marker. Do not wrap it in an outer transaction.

It replaces the original prompt/budget constraints with a validated combined
constraint. Legacy rows keep 8,000/180,000 and their original prompt/timestamps;
no data update, backfill or default change occurs. A new initial hosted Sol attempt
uses `creation-hosted-sol-v1`, partner consent, 16,000 output tokens (including
reasoning), 240,000 ms provider timeout and an observation deadline exactly 270
seconds after reservation. The existing insert trigger supplies these values;
runtime receives no new column grants.

Only four existing SECURITY INVOKER functions are replaced: attempt guard, attempt
reader, reservation and completion. Replacement retains signatures, owner/ACLs,
session/owner/payment checks, lock ordering, immutable identity, primary-key allowance,
terminal-state behavior and idempotent completion. Completion validates output
against the immutable recorded allowance. The reader returns that recorded budget.
Legacy Sol with the original prompt retains its Development project restriction.

The hosted marker is selected only by server policy; it is not an SQL attestation
of Vercel environment or wallet allowlist. Existing verified-session, admission,
endpoint and action guards remain responsible for platform authorization. The
previously accepted trusted-runtime SQL boundary is unchanged.

There is no new table, role, GRANT, wallet/payment/publication permission, provider
retry, or recovery mechanism. No experimental recovery migration is included.

## Timeout rationale

The accepted initial Sol attempt exhausted 8,000 tokens; the accepted 16,000-token
Development recovery succeeded. That supports the larger output budget. Its
420-second timeout is unsuitable for a 300-second hosted route and is not reused.
The hosted 240-second provider timeout leaves 60 seconds for authorization/source
reads, validation and saving. The 270-second observation window gives saving margin
after dispatch; expiry remains uncertainty and never renews the allowance. Real
hosted completion latency at these limits remains unverified; no paid inference ran.
